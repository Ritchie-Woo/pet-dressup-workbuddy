# 地图地点半自动采集方案

> 范围：只描述宠物友好地点进入 `mp_place` 前的线索整理、人工审核和入库流程；不在本次开发中执行抖音、小红书、公众号的真实外部采集。

## 1. 目标

为地图模块补充可追溯的地点数据流程，确保外部平台线索必须先进入人工审核，不直接写入线上地点库。

## 2. 线索来源

允许进入候选池的线索类型：

- 抖音公开内容线索：仅记录人工发现的地点名称、城市、地址描述、来源链接或备注。
- 小红书公开内容线索：仅记录人工发现的地点名称、城市、地址描述、来源链接或备注。
- 公众号文章线索：记录文章标题、链接、发布时间、地点描述。
- 用户投稿：来自小程序投稿表单，默认状态为 `pending`。
- 人工确认：运营或测试人员现场确认或电话确认后的补充信息。
- 开发种子数据：仅用于开发和测试，标记为 `dev_seed` 或 `test_seed`。

## 3. 候选字段

候选记录建议包含：

- `name`：地点名称。
- `category`：`mall / restaurant / park / hotel / adoption / other`。
- `city`：城市。
- `address_raw`：原始地址描述。
- `pet_policy_raw`：原始宠物友好说明。
- `source`：`douyin / xiaohongshu / official_account / user_submitted / manual_confirmed / dev_seed / test_seed`。
- `source_url`：来源链接，没有链接时记录来源备注。
- `source_date`：来源内容时间或人工记录时间。
- `review_status`：`pending / approved / rejected / needs_more_info`。
- `review_note`：审核备注。

## 4. 标准化

候选线索进入审核前需要做最小标准化：

- 地点名称去掉营销前缀、emoji 和无关括号。
- 分类映射到目标 6 类，不再使用旧分类如 `cafe / pet_store / hospital`。
- 地址拆成城市、区县、详细地址；地址不清晰时标记 `needs_more_info`。
- 宠物政策保留可验证描述，例如“户外区域可携宠”“需牵绳”“需提前预约”。
- 同名同地址候选合并，保留多个来源记录。

## 5. 地理编码

地理编码只对候选池执行，不直接改线上地点：

1. 用地点名称 + 城市 + 地址描述生成 geocode 查询。
2. 若返回多个候选，人工选择最匹配结果。
3. 若坐标与地址城市不一致，标记 `needs_more_info`。
4. 坐标确认后写入候选记录的 `latitude / longitude`。
5. 只有审核通过后，坐标才进入 `mp_place`。

## 6. 人工审核

审核人员逐条确认：

- 地点是否真实存在。
- 分类是否符合目标分类。
- 地址和坐标是否一致。
- 宠物友好描述是否足够明确。
- 来源是否可追溯。
- 是否与已有 `mp_place` 重复。

审核结果：

- `approved`：允许写入或更新 `mp_place`。
- `rejected`：不写入，记录原因。
- `needs_more_info`：暂不写入，等待补充信息。

## 7. 入库规则

审核通过后写入 `mp_place`：

- 新地点：写入 `name/category/address/latitude/longitude/pet_policy/source/status`。
- `status` 固定为 `approved`。
- `created_at` 记录首次入库时间。
- `updated_at` 记录最近一次人工确认或信息更新。
- 来源类型写入 `source`，详情页展示为用户可读来源。

## 8. 更新规则

已有地点更新时：

- 只更新被人工确认过的字段。
- 不覆盖用户照片、打卡、标签投票等用户生成内容。
- 地址或坐标变更必须重新审核。
- 宠物政策变更要记录 `updated_at`。
- 发现地点已关闭或不再宠物友好时，先标记为待复核，不直接删除记录。

## 9. 禁止项

- 不绕过人工审核直接写入 `mp_place`。
- 不执行自动批量抓取抖音、小红书、公众号内容。
- 不保存无授权的图片、视频或用户个人信息。
- 不删除线上地点集合或历史用户行为数据。
